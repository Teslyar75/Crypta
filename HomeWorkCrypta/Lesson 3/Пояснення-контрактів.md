# Детальне пояснення контрактів Solidity

## Загальні концепції

### Що таке смарт-контракт?
Смарт-контракт — це програма, розміщена в блокчейні. Вона виконується автоматично при виклику функцій і зберігає стан (змінні) між викликами.

### Ключові типи функцій
- **view** / **pure** — не змінюють стан, не коштують gas при читанні ззовні
- **public** — можна викликати ззовні та з контракту
- **private** — тільки всередині контракту

### Глобальні змінні
- **msg.sender** — адреса того, хто викликав функцію
- **msg.value** — сума в wei, надіслана з транзакцією
- **block.timestamp** — поточний час блоку

---

## 1. Контракт-лічильник

### Ідея
Найпростіший контракт для збереження одного числа та його зміни.

### Ключові елементи
```solidity
int256 private count;  // приватна змінна — не видна ззовні
```
- **int256** — ціле число зі знаком (може бути від'ємним)
- **private** — доступ лише всередині контракту

### Функції
- `increment()` — збільшує на 1
- `decrement()` — зменшує на 1
- `getCount()` — повертає поточне значення (view — не змінює стан)

### Чому view?
`getCount()` тільки читає дані, тому `view` — це економія gas при виклику з інших контрактів або через RPC без відправки транзакції.

## 2. Список задач

### Ідея
Масив рядків з можливістю додавання та видалення.

### Видалення за індексом
У Solidity немає вбудованого `delete` для елемента масиву. Використовуємо трюк:
1. Замінюємо елемент, що видаляється, останнім елементом
2. Викликаємо `pop()` — прибираємо останній

Це дає O(1) замість O(n) при перебудові масиву.

### memory vs storage
```solidity
string memory _task  // параметр — завжди memory
```
- **memory** — тимчасове зберігання на час виконання
- **storage** — постійне зберігання в блокчейні

## 3. Магазин товарів

### Структура Product
```solidity
struct Product {
    string name;
    uint256 price;
    bool exists;  // для "проданих" товарів
}
```

### msg.value
Коли користувач викликає `buyProduct`, він надсилає ETH разом з транзакцією. `msg.value` — це сума в **wei** (1 ETH = 10^18 wei).

### Перевірка та решта
```solidity
require(msg.value >= product.price, "Insufficient balance");
uint256 change = msg.value - product.price;
if (change > 0) {
    payable(msg.sender).transfer(change);  // повертаємо решту
}
```

### payable
- `payable(address)` — перетворює адресу на ту, куди можна надсилати ETH
- `transfer()` — надсилає ETH (обмеження 2300 gas, безпечніше використовувати `call`)

### Роль owner
Тільки власник контракту (`msg.sender` при деплої) може додавати товари.

## 4. Голосування

### Конструктор з параметрами
```solidity
constructor(string[] memory _candidateNames) {
    for (uint256 i = 0; i < _candidateNames.length; i++) {
        candidates.push(Candidate(_candidateNames[i], 0));
    }
}
```
При деплої передаємо масив імен кандидатів.

### Захист від подвійного голосу
```solidity
mapping(address => bool) public hasVoted;
require(!hasVoted[msg.sender], "Already voted");
hasVoted[msg.sender] = true;
```
Кожна адреса може проголосувати лише один раз.

### Повернення кількох значень
```solidity
function getResults() public view returns (
    string[] memory names,
    uint256[] memory votes
) {
    // ...
}
```
Solidity дозволяє повертати кілька значень. Для масивів потрібно спочатку їх створити з фіксованим розміром.

## 5. Підписки

### Час підписки
```solidity
uint256 duration = 30 days;  // Solidity розуміє: 30 * 24 * 60 * 60
subscriptionEnd[_user] = block.timestamp + duration;
```

### Продовження підписки
Якщо підписка ще активна, додаємо 30 днів до поточного кінця:
```solidity
if (subscriptionEnd[msg.sender] > block.timestamp) {
    subscriptionEnd[msg.sender] += duration;
} else {
    subscriptionEnd[msg.sender] = block.timestamp + duration;
}
```

### Роль адміністратора
Тільки `admin` може змінювати ціну підписки через `setSubscriptionPrice`.

## 6. Фінансування проєктів

### Структура проєкту
- **proposer** — хто запропонував
- **description** — опис
- **requiredAmount** — потрібна сума
- **votes** — кількість голосів
- **funded** — чи вже отримав фінансування

### Двовимірний mapping
```solidity
mapping(uint256 => mapping(address => bool)) public hasVotedForProject;
```
`hasVotedForProject[projectId][userAddress]` — чи голосував цей користувач за цей проєкт.

### receive()
```solidity
receive() external payable {
    treasury += msg.value;
}
```
Дозволяє контракту приймати ETH при звичайному переказі (без виклику функції).

### Логіка фінансування
1. Користувачі поповнюють `treasury` (receive або depositToTreasury)
2. Пропонують проєкти
3. Голосують за проєкти
4. Будь-хто викликає `fundProject(index)` — кошти переходять пропоненту
5. У реальному варіанті можна додати: фінансувати тільки проєкт з найбільшою кількістю голосів, або розподіл пропорційно голосам

## Як тестувати контракти

### Remix (remix.ethereum.org)
1. Створити файл, вставити код
2. Compile (версія Solidity 0.8.x)
3. Deploy — для Voting передати масив: `["Alice","Bob","Carol"]`
4. Викликати функції через інтерфейс

### Окремий деплой контрактів
У файлі всі контракти в одному .sol — при деплої вибираєш потрібний (Counter, TaskList, Shop тощо). Конструктори:
- **Counter** — без параметрів
- **TaskList** — без параметрів
- **Shop** — без параметрів
- **Voting** — `["Кандидат1","Кандидат2"]`
- **Subscription** — ціна в wei, наприклад `1000000000000000000` (1 ETH)
- **CommunityFunding** — без параметрів

## Поради з безпеки

1. **require** — перевіряй умови на початку функцій
2. **reentrancy** — для переказів краще використовувати патерн Checks-Effects-Interactions
3. **overflow** — Solidity 0.8+ автоматично перевіряє overflow
4. **access control** — обмежуй критичні функції (owner, admin)
