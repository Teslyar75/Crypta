# Як створюються токени — розгорнута довідка

## Загальні поняття

### Що таке токен?
Токен — це цифровий актив на базі існуючого блокчейну. На відміну від нативної монети (ETH, BTC), токен створюється смарт-контрактом і не має власного блокчейну.

### Стандарти токенів
- **ERC-20** (Ethereum) — найпоширеніший для взаємозамінних токенів
- **BEP-20** (BNB Chain) — аналог для мережі Binance
- **SPL** (Solana) — токени в мережі Solana
- **TRC-20** (TRON) — токени в мережі TRON

## Крок 1: Вибір блокчейну

| Блокчейн | Плюси | Мінуси | Комісії |
|----------|-------|--------|---------|
| **Ethereum** | Найбільша екосистема, біржі, гаманці | Високі gas fees | Високі при навантаженні |
| **Polygon** | Дешево, швидко, сумісність з ETH | Менша децентралізація | Дуже низькі |
| **BNB Chain** | Швидко, дешево | Централізація Binance | Низькі |
| **Solana** | Дуже швидко, дешево | Історія збоїв мережі | Мінімальні |

## Крок 2: Написання смарт-контракту

### Базовий ERC-20 контракт містить:

```solidity
// Спрощена структура
contract MyToken {
    string public name = "My Token";
    string public symbol = "MTK";
    uint8 public decimals = 18;
    uint256 public totalSupply;
    
    mapping(address => uint256) public balanceOf;
    
    function mint(address to, uint256 amount) public { ... }
    function transfer(address to, uint256 amount) public { ... }
    function burn(uint256 amount) public { ... }
}
```

### Ключові функції:
- **mint** — створення нових токенів (мінтінгу)
- **transfer** — переказ
- **burn** — знищення токенів
- **approve** / **transferFrom** — для делегації (DEX, біржі)

---

## Крок 3: Процес мінтінгу

### Типи мінтінгу:

1. **Одноразовий** — при деплої контракту мінтяться всі токени одразу
2. **Поетапний** — мінт за розкладом (наприклад, щомісяця)
3. **Умовний** — мінт при виконанні умов (нагорода за дію, proof-of-work)
4. **Динамічний** — кількість залежить від змінних (ціна, час)

### Мінтінгувач (minter):
- Може бути лише адреса власника контракту
- Або окремий смарт-контракт (орієнтований на логіку)
- Важливо обмежити права для безпеки

---

## Крок 4: Деплой та верифікація

1. **Компіляція** — Solidity → bytecode (Hardhat, Remix)
2. **Деплой** — відправка транзакції створення контракту в мережу
3. **Верифікація** — публікація вихідного коду на Etherscan для прозорості
4. **Тестування** — тестова мережа (Goerli, Sepolia) перед mainnet

---

## Крок 5: Інструменти

| Інструмент | Призначення |
|------------|-------------|
| **Remix** | Онлайн IDE для Solidity, деплой без налаштувань |
| **Hardhat** | Локальна розробка, тести, скрипти деплою |
| **OpenZeppelin** | Готові безпечні контракти (ERC-20, Ownable, Pausable) |
| **Thirdweb** | No-code створення токенів через інтерфейс |
| **Token Factory** | Сервіси для швидкого створення без коду |

---

## Безпека та юридичні аспекти

- **Аудит коду** — перевірка контракту перед запуском
- **Обмеження мінту** — cap (максимум токенів) запобігає інфляції
- **Pausable** — можливість зупинити перекази при виявленні проблем
- **Юридична відповідність** — токен може бути цінним папером (security token), потрібна консультація юриста

---

## Приклад: створення токену за 5 хвилин (Remix)

1. Відкрити [remix.ethereum.org](https://remix.ethereum.org)
2. Створити файл `Token.sol` з контрактом ERC-20 (OpenZeppelin)
3. Компілювати (Compile)
4. Підключити MetaMask до Sepolia (тестова мережа)
5. Деплой (Deploy) → отримати адресу контракту
6. Додати токен у MetaMask за адресою контракту

---

## Підсумок

Створення токену — це написання смарт-контракту, його деплой у блокчейн та налаштування логіки мінтінгу. Для концептуального розуміння достатньо знати стандарти, блокчейни та типи мінтінгу. Для реального запуску потрібні знання Solidity, тестування та увага до безпеки.
