# Криптография в блокчейне

## 🔐 Основы криптографии

**Криптография** — наука о защите информации с помощью математических методов.

**В блокчейне используется для**:
- Защиты транзакций
- Создания цифровых подписей
- Генерации адресов
- Связывания блоков

## 🔑 Криптография с открытым ключом

### Принцип работы

**Два ключа**:
1. **Приватный ключ** (Private Key) — секретный, только у владельца
2. **Публичный ключ** (Public Key) — открытый, можно делиться

**Математическая связь**:
```
Публичный ключ = f(Приватный ключ)
```

**Важно**: Из публичного ключа нельзя вычислить приватный!

### Пример использования

```
Шифрование:
Боб шифрует сообщение публичным ключом Алисы
→ Только Алиса может расшифровать приватным ключом

Подпись:
Алиса подписывает сообщение приватным ключом
→ Все могут проверить подпись публичным ключом
```

## 🔏 Хеш-функции

### Что такое хеш?

**Определение**: Функция, которая превращает любые данные в строку фиксированной длины.

**Пример SHA-256**:
```
Вход: "Hello"
Выход: 185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969

Вход: "Hello!"
Выход: 334d016f755cd6dc58c53a86e183882f8ec14f52fb05345887c8a5edd42c87b7
```

### Свойства хеш-функций

1. **Детерминированность**: Одинаковый вход → одинаковый выход
2. **Быстрое вычисление**: Легко вычислить хеш
3. **Необратимость**: Нельзя восстановить исходные данные
4. **Лавинный эффект**: Малое изменение → полностью другой хеш
5. **Устойчивость к коллизиям**: Сложно найти два разных входа с одинаковым хешем

### Использование в блокчейне

```
1. Идентификация блоков
   Блок → SHA-256 → Уникальный ID

2. Связывание блоков
   Блок N содержит хеш Блока N-1

3. Proof of Work
   Найти nonce: SHA-256(блок + nonce) < цель

4. Merkle Tree
   Эффективная проверка транзакций
```

## ✍️ Цифровые подписи

### Как работает подпись?

**Создание подписи**:
```
1. Алиса создает транзакцию
2. Вычисляет хеш транзакции
3. Подписывает хеш приватным ключом
4. Подпись + транзакция → в сеть
```

**Проверка подписи**:
```
1. Боб получает транзакцию + подпись
2. Вычисляет хеш транзакции
3. Проверяет подпись публичным ключом Алисы
4. Если совпадает → подпись валидна
```

### Алгоритм ECDSA

**ECDSA** (Elliptic Curve Digital Signature Algorithm) — используется в Bitcoin

**Преимущества**:
- Короткие ключи (256 бит)
- Высокая безопасность
- Быстрая проверка

**Процесс**:
```
Приватный ключ (256 бит случайное число)
    ↓
Публичный ключ (точка на эллиптической кривой)
<!-- Эллиптическая кривая — это математическая кривая вида y² = x³ + ax + b. В криптографии (например, secp256k1 в Bitcoin) на ней задана операция «сложения» точек. Публичный ключ получается умножением базовой точки G на приватный ключ: PubKey = PrivKey × G. Результат — координаты (x, y) точки на кривой. Из приватного ключа легко вычислить публичный, но обратное невозможно — это односторонняя функция, обеспечивающая безопасность. -->
    ↓
Адрес (хеш публичного ключа)
```

## 🏠 Генерация адресов

### Bitcoin адрес

**Процесс создания**:
```
1. Генерация приватного ключа (256-битное случайное число)
   Пример: 5Kb8kLf9zgWQnogidDA76MzPL6TsZZY36hWXMssSzNydYXYB9KF

2. Вычисление публичного ключа (ECDSA)
   Пример: 04678afdb0fe5548271967f1a67130b7105cd6a828e03909a67962e0ea1f61deb649f6bc3f4cef38c4f35504e51ec112de5c384df7ba0b8d578a4c702b6bf11d5f

3. Хеширование SHA-256
   
4. Хеширование RIPEMD-160
   
5. Добавление версии и контрольной суммы
   
6. Кодирование Base58
   Адрес: 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa
```

### Ethereum адрес

**Процесс**:
```
1. Приватный ключ
2. Публичный ключ (ECDSA)
3. Keccak-256 хеш
4. Последние 20 байт
5. Добавление "0x"

Адрес: 0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb
```

## 🛡️ Безопасность

### Энтропия и случайность

**Критически важно**: Приватный ключ должен быть действительно случайным!

**Плохой пример**:
```python
# НЕ ДЕЛАЙ ТАК!
private_key = "password123"
```

**Хороший пример**:
```python
import secrets
private_key = secrets.token_bytes(32)
```

### Атаки на криптографию

**1. Brute Force (Перебор)**
- Попытка угадать приватный ключ
- Для 256-бит ключа: 2^256 вариантов
- Практически невозможно

**2. Атака на хеш-функцию**
- Поиск коллизий
- SHA-256 считается безопасной

**3. Квантовые компьютеры**
- Потенциальная угроза в будущем
- Разработка квантово-устойчивой криптографии

## 📊 Сравнение алгоритмов

| RIPEMD-160 | Хеш     | Bitcoin адреса      | -            |

## 🔬 Практический пример

### Простая демонстрация хеширования

```python
import hashlib

# Хеширование строки
data = "Hello, Blockchain!"
hash_object = hashlib.sha256(data.encode())
hash_hex = hash_object.hexdigest()

print(f"Данные: {data}")
print(f"SHA-256: {hash_hex}")

# Малое изменение
data2 = "Hello, Blockchain!!"
hash_object2 = hashlib.sha256(data2.encode())
hash_hex2 = hash_object2.hexdigest()

print(f"\nДанные: {data2}")
print(f"SHA-256: {hash_hex2}")
print(f"\nХеши полностью разные!")
```
